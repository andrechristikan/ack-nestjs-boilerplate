# Add a queue or a job

Invariants: `.claude/rules/queue.md`, `.claude/rules/outbox.md`, `.claude/rules/effects.md`. Reference implementation: the `workspace` queue (one job, a scheduler) and the `notificationEmail` queue (many jobs, encrypted fields, a rate limiter). Framework files live in `src/common/queue/`.

## New queue

1. Name it: add a camelCase member to `Enum<Module>Queue` in `src/modules/<module>/enums/<module>.enum.ts` (`EnumWorkspaceQueue`); its value is the Redis queue name.
2. Config: add `<name>BackoffDelayInMs` to `IConfigQueue` `job` and its value (`src/configs/queue.config.ts`). `attempts`, `keepLogs`, and the removal ages are shared.
3. Factory: `src/modules/<module>/factories/<module>[.<concern>].queue.factory.ts`, class `<Module>[<Concern>]QueueFactory`, `implements RegisterQueueOptionsFactory`, returning `defaultJobOptions` alone, from `queue.job.*` (`src/modules/workspace/factories/workspace.queue.factory.ts`); the queue inherits the rest from `QueueModule.forRoot()` (`.claude/rules/queue.md`).
4. Register in the feature's `<module>.module.ts`: one `{ name: Enum<Module>Queue.<member>, useClass: <Module>[<Concern>]QueueFactory }` object in its one `BullModule.registerQueueAsync` call in `imports` (`src/modules/workspace/workspace.module.ts`). The queue kit registers no queue; the cache kit registers only `cache` (`.claude/rules/cache.md`).
5. Queue class, only when the queue schedules a recurring job: `queues/<module>[.<concern>].queue.ts`, `@Injectable()`, `extends QueueBase` (`src/common/queue/bases/queue.base.ts`), constructor `(@InjectQueue(Enum<Module>Queue.<member>) protected readonly queue: Queue, protected readonly cacheService: CacheService, private readonly configService: ConfigService)` with `super(queue, cacheService)`; provided by `<module>.module.ts`, never exported or injected (`src/modules/workspace/queues/workspace.queue.ts`). One class per queue; no header interface.
6. Processor: `processors/<module>[.<concern>].processor.ts`, `@QueueProcessor(Enum<Module>Queue.<member>, options?)`, `extends QueueProcessorBase`, constructor `(protected readonly sentryService: SentryService, protected readonly messageService: MessageService, protected readonly cacheService: CacheService, protected readonly outboxService: OutboxService, private readonly <x>UseCase, ...)` with `super(sentryService, messageService, cacheService, outboxService)`, `protected async handle(job, data, outboxId)` switching on `job.name` and awaiting one use case's `execute` per case (`src/modules/workspace/processors/workspace.processor.ts`). The `default` case throws `new QueueException(<the error.unknownProcess message>, true)` itself, the message built through `this.messageService`, and returns no `IQueueResponse`; the processor injects `MessageService` only to forward it to `super` and to build that message and the message of an `UnrecoverableError` it throws for a payload it rejects (`.claude/rules/queue.md`, Processors). Worker options such as a limiter go in the decorator's second argument (`src/modules/notification/processors/notification.email.processor.ts`).
7. Use case per job: `use-cases/<module>[.<concern>].process-<action>.use-case.ts`, class `<Module>[<Concern>]Process<Action>UseCase` implementing `IAppUseCase<[<execute params>], IQueueResponse>`, injects `MessageService`, `execute(data)` takes the payload `handle` passes and calls a service, returns `IQueueResponse` with `message: this.messageService.setMessage('<module>.queue.[<channel>.]<process>', { properties })`, and throws `new QueueException(this.messageService.setMessage('<module>.queue.[<channel>.]error.<descriptor>', { properties }), true)`, or `(message, true, error)` to carry the cause, the channel segment present only where the module runs several queues (`src/modules/workspace/use-cases/workspace.process-expire-stale-invites.use-case.ts`; `.claude/rules/queue.md`, Messages). A recurring job is scheduled from the queue class's own `onModuleInit`.
8. Use-case module: `<module>.use-case.module.ts` providing and exporting the use cases, importing `<Module>Module` unless the feature is `@Global()` (`src/modules/workspace/workspace.use-case.module.ts`).
9. Aggregate: add the processor to `providers` and the use-case module to `imports` of `src/router/processor/router.processor.module.ts`.
10. Messages: add `queue.[<channel>.]<process>`, `queue.[<channel>.]error.<descriptor>`, and `queue.[<channel>.]error.unknownProcess` (placeholder `{process}`) under the top-level `"queue"` object of `src/languages/<lang>/<module>.json`, every language; a second queue on a module nests its keys under its channel name (`.claude/rules/i18n.md`).

## New job on an existing queue

1. Job name: a member of the module's process enum, `Enum<Module>Process` in `<module>/enums/<module>.enum.ts` (`EnumWorkspaceProcess` in `src/modules/workspace/enums/workspace.enum.ts`; `EnumNotificationProcess` in `src/modules/notification/enums/notification.enum.ts`).
2. Payload in `<module>/interfaces/<module>.interface.ts`, camelCase fields: the envelope `I<Module>[<Channel>][Bulk]QueuePayload<T>` carries the data `I<Module><Action>Payload`, `I<Module><Action>EncryptedPayload` once a field is encrypted (`ISessionPurgeLoginsPayload`, `src/modules/session/interfaces/session.interface.ts`).
3. Producer. A side effect of a write is an outbox effect: a `<action>Effect` method on the owning module's service returns the job's `I<Module><Action>Effect`, declared in the owning module's interface file, with its priority and `idempotencyKey` (`.claude/rules/effects.md`, Effects). A scheduler is a queue-class method instead: `upsertJobScheduler` from the queue class's own `onModuleInit` (`src/modules/workspace/queues/workspace.queue.ts`); a failure throws. A sensitive field is encrypted where the payload is built, with `HelperEncryptionService.aes256Encrypt`, the root secret, the module's `*EncryptionPurpose` constant, and as context the id the value belongs to; it is named `encrypted<Field>` (`NotificationService.notify`, `src/modules/notification/services/notification.service.ts`).
4. Processor case: one `case` in `handle` awaiting the use case's `execute` (`src/modules/notification/processors/notification.email.processor.ts`). A failure no retry fixes is thrown as `UnrecoverableError` inside `handle`. Its catch rethrows `QueueException`, `AppBaseException`, or `UnrecoverableError` as is and throws an unknown error with `this.throwUnknownException(error);`: a `QueueException` with the `queue.error.unknown` message, `isFatal` `true`, and the error as `rawError`.
5. Use case: `execute(data)` translates the payload and calls the service (`src/modules/workspace/use-cases/workspace.process-expire-stale-invites.use-case.ts`); the `IQueueResponse` carries the `<module>.queue.[<channel>.]<process>` message, built as New queue step 7 states, its keys added per step 10.
6. Caller: an effect goes into the caller's transaction (`.claude/rules/effects.md`, Writing); a caller in another module calls the owning service's `<action>Effect` as `.claude/rules/layering.md`, Dependency order, allows.

## Rename

Renaming a queue, a job name, or a payload field changes every producer, processor, and payload type in the same change (`.claude/rules/queue.md`, Processors).

## Verify

```bash
pnpm typecheck
pnpm test <module>
```

Boot in the Docker `apis` container (`.claude/skills/ack-build/references/boot.md`): the worker registers there. Check the boot log for the `App Name:` block and the `<Module>UseCaseModule dependencies initialized` line, BullMQ logging no line per worker.

Specs: an effect builder asserts queue, name, data, priority, and key; the queue class asserts the scheduler's job name and options; a use case asserts the hand-off and the message path it resolves; the processor holds the `unknownProcess` throw and its file is excluded from coverage (`.claude/rules/testing.md`). BullBoard shows the queue at the port in `docker-compose.yml`.
