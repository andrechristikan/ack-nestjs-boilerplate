# Security

MFA: `mfa.md`. Sessions: `session.md`. Sign-in: `login.md`. Authorization: `role.md`. Activity log: `activity-entry.md`.

## Credentials

A credential: a password hash or generated password; a TOTP secret, pending secret, backup code; a raw access, refresh, verification, reset, or invite token; a social sign-in nonce; an API key secret, encryption root, JWT private key, presign signature.

- Never in a log line, an error message, `JSON.stringify`, a URL path, activity metadata, a Sentry attribute, or `request.<field>`. Redaction (`logging.md`) is only a safety net.
- A plaintext credential enters a database row, cache entry, or job payload only sealed: a value only compared (token, one-time code such as `Verification.token`, API key secret, the session jti as `Session.jtiDigest`, an MFA challenge as `MfaChallenge.tokenHash`, the social nonce as `AuthSocialNonce.nonceHash`) as its SHA-256 hash, a backup code as its argon2id hash, a value read back (TOTP secret, queued password or link) encrypted. In memory it rides plain; on the wire, only what the response schema declares. A passkey public key, a WebAuthn challenge, and a device push token are no credential and stored plain, the push token as `DeviceOwnership.notificationToken`, read back and looked up by value; a job payload and an `MfaChallenge` carry it sealed (`MfaChallengeEncryptionPurpose`).
- Job and outbox payloads: `effects.md`, Payloads.

## Cryptography

- `node:crypto` runs only through the `Helper*` services, DER-to-PEM key framing included (`HelperEncryptionService.derBase64ToPem`). A token, code, password, or key draws from `HelperStringService` / `HelperNumberService`; a row id is `DatabaseUtil.createId()`.
- `HelperEncryptionService.aes256Encrypt` / `aes256Decrypt(value, secret, purpose, context)`: AES-256-GCM, an HKDF-SHA-256 key over the root, a per-payload salt, and `purpose`, with `context` as authenticated data. `purpose` is one constant per use, owned by the encrypting module (`MfaTotpSecretEncryptionPurpose`); `context` is the owning id; the ownerless cursor token uses the fixed `PaginationCursorEncryptionContext`.
- Root secrets (`APP_ENCRYPTION_SECRET`, `MFA_TOTP_ENCRYPTION_SECRET`) are 48 random bytes (64 base64url characters), separate roots, generated by `pnpm generate:secret` into `keys/`. A root has no rotation path: a payload names no key, and replacing a root invalidates what it sealed.
- Hashing is SHA-256 (`HelperHashService.sha256Hash`) for lookups and one-time codes, argon2id (`argon2Hash`, `argon2Compare`, `helper.argon2`) for passwords and backup codes. A secret comparison is `HelperHashService.sha256Compare` (`timingSafeEqual`); `===` is the defect.

## Contact values

An email address and a mobile number are censored in every response outside the `/admin` scope: the non-admin use case passes what it returns through `HelperStringService.censorEmail` and `censorMobileNumber`, and the stored row, its effects, and an `/admin` response carry the full value. A response schema carries no censor transform, since one schema may serve both scopes.

## Response headers

`RequestHelmetMiddleware` sends `RequestHelmetCspDirectives`, `Referrer-Policy: no-referrer`, and `Cache-Control: no-store` on every route it handles, and a route with another cache policy sets its own header (the health routes); the Swagger routes register before module middleware, so `src/swagger.ts` sets `RequestHelmetCspDocDirectives` and the referrer policy with helmet's standalone middlewares ahead of `SwaggerModule.setup`. A directive widens only for a blocked load a browser reports.

## Request store

Per-request state lives in `RequestStoreService`, keyed by `*StoreKey` constants; add a key, never a second store. `IRequestApp` carries the transport only (`id`, `correlationId`). Each module owns its context: its guard or middleware translates a credential or header into `I<Module>[<Concern>]Context` under its own `<Module>[<Concern>]ContextStoreKey`; every reader takes the context, and no code stores a JWT or provider payload. The JWT guards write the kit's `RequestActorStoreKey` (the user id) for the logger, audit stamping, and the per-user throttle. A guard, middleware, or interceptor injects it, and the kit reads it (`DatabaseExtensionFactory` audit stamping, `ResponseMetadataService`, the logger mixin); a param decorator: `guards.md`. A service, use case, effect builder, or processor never reads it (a list use case's `PaginationStoreKey` merge is a write, `pagination.md`): the controller passes the contexts down (`http.md`, `service.md`), and the raw refresh token lives in `IAuthJwtRefreshContext` only, never in a job payload or a log. `RequestRequestIdMiddleware`, first in the `RequestMiddlewareModule` chain, alone writes `req.id`, `req.correlationId`, and both id store keys (`logging.md`). `IRequestContext.requestLog` holds the client IP, user agent, and geo-location, resolved once per request (`request.request-log.middleware.ts`). The client IP is `req.ip` under `trust proxy` (`src/configure.ts:38`).
