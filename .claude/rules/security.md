# Security

Two-factor, session invalidation, sign-in, and authorization: `auth.md`. The activity log: `activity-log.md`.

## Credentials

A credential: a password hash or generated password; a 2FA secret, pending secret, backup code; a raw access, refresh, verification, reset, or invite token; an API key secret, encryption root, JWT private key, presign signature.

- Never in a log line, an error message, `JSON.stringify`, a URL path, activity metadata, a Sentry attribute, or `request.<field>`. Redaction (`logging.md`) is only a safety net.
- A plaintext credential enters a database row, cache entry, or job payload only sealed: a value only compared (backup code, token, API key secret) as its SHA-256 hash, a value read back (2FA secret, queued password or link) encrypted. In memory it rides plain; on the wire, only what the response schema declares.

## Cryptography

- `node:crypto` runs only through the `Helper*` services, DER-to-PEM key framing included (`HelperEncryptionService.derBase64ToPem`). A token, code, password, or key draws from `HelperStringService` / `HelperNumberService`; a row id is `DatabaseUtil.createId()`.
- `HelperEncryptionService.aes256Encrypt` / `aes256Decrypt(value, secret, purpose, context)`: AES-256-GCM, an HKDF-SHA-256 key over the root, a per-payload salt, and `purpose`, with `context` as authenticated data. `purpose` is one constant per use, owned by the encrypting module (`AuthTwoFactorSecretEncryptionPurpose`); `context` is the owning id, except the cursor token, which uses the fixed `PaginationCursorEncryptionContext` because a token has no owner.
- Root secrets (`APP_ENCRYPTION_SECRET_KEY`, `AUTH_TWO_FACTOR_ENCRYPTION_KEY`) are 48 random bytes (64 base64url characters), separate roots, generated by `pnpm generate:secret` into `keys/`.
- Hashing is SHA-256 (`HelperHashService.sha256Hash`) for lookups, bcrypt for passwords. A secret comparison is `HelperHashService.sha256Compare` (`timingSafeEqual`); `===` is the defect. The one exception: the `SessionCache.updateLogin` Lua script compares the stored and candidate jti SHA-256 digests, hashed through `HelperHashService` before the call; the raw jti never reaches Redis.

## Request store

Per-request state lives in `RequestStoreService`, keyed by `*StoreKey` constants; add a key, never a second store. A class injects it; a param decorator: `guards.md`. `RequestRequestIdMiddleware`, first in the `RequestMiddlewareModule` chain, alone writes `req.id`, `req.correlationId`, and both id store keys (`logging.md`). `RequestLogStoreKey` holds the client IP, user agent, and geo-location, resolved once per request (`request.request-log.middleware.ts`) and never re-resolved. The client IP is `req.ip` under `trust proxy` (`src/configure.ts:38`).
