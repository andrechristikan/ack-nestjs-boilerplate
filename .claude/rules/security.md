# Security

## Credentials

A credential: a password hash or generated password, a 2FA secret, pending secret, or backup code, a raw access
or refresh token, a verification, reset, or invite token, an API key secret, an encryption root, a JWT private key, a presign signature.

- Never in a log line, an error message, a `JSON.stringify`, a URL path, activity metadata, a Sentry attribute,
  a cached response, or `request.<field>`. Redaction (`LoggerSensitiveFields`, `src/instrument.ts`) is a
  safety net, not a licence.
- At rest or in a job payload: a value only compared (backup code, token, API key secret) is its SHA-256 hash;
  a value read back (2FA secret, a queued password or link) is encrypted. On the wire: only what the response
  schema declares. Across a call: explicit plain values, never inside a payload object.

## Cryptography

- `node:crypto` through the `Helper*` services; randomness for a token, code, password, key, or id is
  `randomInt` / `randomBytes` through `HelperStringService` / `HelperNumberService`.
- `HelperEncryptionService.aes256Encrypt` / `aes256Decrypt(value, secret, purpose, context)`
  (`src/common/helper/services/helper.encryption.service.ts:56`): AES-256-GCM, key from HKDF-SHA-256 over the
  root, a per-payload salt, and `purpose`; `context` bound as authenticated data. `purpose` is a constant
  owned by the encrypting module (`AuthTwoFactorSecretEncryptionPurpose`,
  `NotificationPayloadEncryptionPurpose`), one per use; `context` is the id the value belongs to.
- Root secrets (`APP_ENCRYPTION_SECRET_KEY`, `AUTH_TWO_FACTOR_ENCRYPTION_KEY`) are 48 random bytes as exactly
  64 base64url characters, separate roots, generated by `pnpm generate:secret` into `keys/`, printed as paths.
- Hashing is SHA-256 (`HelperHashService.sha256Hash`) for lookups and bcrypt for passwords. A secret comparison
  is `HelperHashService.sha256Compare` (`helper.hash.service.ts:24`, `timingSafeEqual`); `===` is the defect.

## Two-factor

`TwoFactor.secret` holds only a confirmed authenticator, encrypted with the two-factor root and the user id.
Setup writes `pendingSecret`; confirming moves it into `secret`; disable and admin reset clear both. Setup
while enabled consumes a valid backup code in the same transaction; consumption is a compare-and-set on the
stored list and commits before a token is issued. A missing or undecryptable secret answers
`AuthTwoFactorSecretUnavailableException` (409), reported from the domain.

## Session invalidation

Password change or reset, logout, device removal, account self-deletion, the lockout at the maximum password
attempts, two-factor disable or admin reset, a status change to `blocked` or `inactive`, and an admin revoke of
one or all sessions each revoke the session rows in the database, then purge the session cache after the
commit; the JWT guards read the cache. A named subset: `SessionCache.deleteLogins` (`session.cache.ts:103`);
every session of a user: `SessionDomain.purgeLoginsByUser` (`session.domain.ts:248`). Order: commit, purge,
stage activity rows; a purge failure after the commit is logged and swallowed. `isRevoked: false` is part of
the `where` of every revoke and of refresh rotation; the refresh cache write is conditional on the entry existing.

## Authorization

A guard reads transport inputs and delegates to a domain; the stack is `http.md`. CASL abilities come from the
`Policy` rows on the caller's role; `@PolicyProtected` names subject and actions. A feature flag is never an
authorization boundary (`feature-flag.md`).

## Activity log

`ActivityLogDomain.prepare(input)` (`src/modules/activity-log/domains/activity-log.domain.ts:199`) builds one
event and validates it against `ActivityLogActionContract`; `stagePrepared` (`:226`) puts it on the CLS queue;
`ActivityLogInterceptor` (`APP_INTERCEPTOR`) flushes. Prepare before the write, stage after it; a value only
the write produces is drawn before it (`DatabaseUtil.createId()`) or prepared after the commit.
`prepare({ onError: true })` marks an event flushed on the error path too; an event on a path that always
throws carries it. Every `EnumActivityLogAction` member has a contract row and an `activityLog` i18n key. An
action one user takes on another writes two rows: the actor's under the plain action with `targetUserId`, the
affected user's under the paired `…ByAdmin` / `…ByOwner` / `…ByInvitee` action with `actorUserId`.

## Request store

Per-request state lives in `RequestStoreService` (`src/common/request/services/request.store.service.ts`),
keyed by `*StoreKey` constants in the owning module's `<module>.constant.ts`; add a key rather than a second
store. `RequestActorStoreKey` is the actor audit stamping reads; `RequestLogStoreKey` holds the once-resolved
geo-location and user-agent. A class injects `RequestStoreService`; a param decorator reads CLS through
`ClsServiceManager.getClsService()` and throws `RequestContextMissingException` when its key or field is missing.
