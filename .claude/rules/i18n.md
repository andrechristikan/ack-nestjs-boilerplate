# i18n messages

Translations live in `src/languages/<lang>/<module>.json`, loaded by nestjs-i18n through `MessageModule.forRoot()` (`src/common/message/message.module.ts`). `RequestCustomLanguageMiddleware` (`src/common/request/middlewares/request.custom-language.middleware.ts`) resolves the language: an `x-custom-lang` value in `message.availableLanguage` wins, anything else falls back to `message.language`; it stores the result under `RequestLanguageStoreKey`, and the filters and response interceptors pass it to `MessageService` as `customLanguage`.

## The path is the file plus the nested key

`user.error.notFound` resolves to `src/languages/<lang>/user.json` → `{ "error": { "notFound": "…" } }`. The first segment is the file name, camelCase, matching the module (`featureFlag.json`, `termPolicy.json`, `apiKey.json`, `activityLog.json`); every segment is camelCase. A flat string key (`"error.notFound": "…"`) does not resolve and fails nothing at build time; the client receives the raw path. Success messages sit at the top level keyed by action (`"list"`, `"create"`), or one level under a sub-resource (`workspace.invite.create`, `user.twoFactor.enable`); errors sit under `"error"`. Queue text sits under a top-level `"queue"` object, its path `<module>.queue.[<channel>.]<process>` or `<module>.queue.[<channel>.]error.<descriptor>`:

- A module running one queue has no channel segment: `{ "queue": { "<process>": "…", "error": { "<descriptor>": "…" } } }`.
- A module running several queues keys the queue named for the module at the top and nests each channel queue under its lowercase channel name, an `EnumNotificationChannel` value (`email`, `push`): `{ "queue": { "<process>": "…", "error": { … }, "email": { "<process>": "…", "error": { … } }, "push": { … } } }`.
- The notification module runs three: `EnumQueue.notification` writes `notification.queue.<process>`, `notificationEmail` writes `notification.queue.email.<process>`, `notificationPush` writes `notification.queue.push.<process>`.

## Every key lands in every language directory

A key added to one directory only resolves to the path string in the others. An exception, a `@Response` message, a validation message, and queue text each add their key everywhere.

| Producer | Path |
| --- | --- |
| an exception | `super('<module>.error.<descriptor>')` (`exceptions.md`) |
| a success response | the `@Response('<module>.<action>')` argument (`http.md`) |
| a validation failure | `request.error.<constraint>`, resolved by `MessageService` |
| a push notification | `notification.notify.<kind>.title` / `.body` (`notification.kind.contract.ts`) |
| an activity-log action | `activityLog.<action>` (`activity-log.util.ts:22`, `security.md`) |
| a job's `IQueueResponse.message` | `<module>.queue.[<channel>.]<process>`, the `Enum<Module>[<Channel>]Process` value (`queue.md`, Messages) |
| a `QueueException` message | `<module>.queue.[<channel>.]error.<descriptor>` (`exceptions.md`, Messages) |
| an unknown job name | `<module>.queue.[<channel>.]error.unknownProcess`, property `process` (`queue.md`, Processors) |
| a side-effect `description` | `<module>.queue.[<channel>.]error.enqueue<Kind>` (`queue.md`, Messages) |

The `@Response` argument is a path, not a sentence.

## Language

- Text for an internal reader (a job return value, a job failure, a side-effect description) resolves in `message.language`: `setMessage(path, { properties })` with no `customLanguage`.
- Text answering a request (a response message, an exception the filter renders, a validation message) resolves in the request's `customLanguage` from `RequestLanguageStoreKey`.
- A log line is not i18n (`code-style.md`, Literal strings).

## Placeholders

`{name}` is fed by `messageProperties`: `super('user.error.importEmailExist', { messageProperties: { emails } })` (`src/modules/user/exceptions/user.import-email-exist.exception.ts:16`). A placeholder with no property renders literally; every language file carries the same placeholder set for a key.

## Renaming a key

The key links an exception's `messagePath` to the JSON. Rename both halves together, in every language, in one change; `tsc` catches nothing.

## Reading a message in code

`MessageService.setMessage(path, options)` (`src/common/message/services/message.service.ts:92`) is the one entry point; a `customLanguage` outside `message.availableLanguage` falls back to `message.language` there (`filterLanguage`). A service never reads a JSON file, concatenates a message, or builds a user-facing sentence.

## Templates are not i18n

A rendered email body or term-policy document is a Handlebars template uploaded as seed data (`queue.md`, `seeding.md`). Template prose stays out of the language JSON, and a status message stays out of a template.
