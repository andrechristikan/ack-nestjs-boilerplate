# i18n messages

Translations live in `src/languages/<lang>/<module>.json`, loaded by nestjs-i18n through `MessageModule.forRoot()` (`src/common/message/message.module.ts`).

## The path is the file plus the nested key

`user.error.notFound` resolves to `src/languages/<lang>/user.json` → `{ "error": { "notFound": "…" } }`. The first segment is the file name, camelCase, matching the module (`featureFlag.json`, `termPolicy.json`, `apiKey.json`, `activityLog.json`); every segment is camelCase. A flat string key (`"error.notFound": "…"`) does not resolve and fails nothing at build time; the client receives the raw path. Success messages sit at the top level keyed by action (`"list"`, `"create"`), or one level under a sub-resource (`workspace.invite.create`, `mfa.totp.enable`); errors sit under `"error"`. Queue text sits under a top-level `"queue"` object, its path `<module>.queue.[<channel>.]<process>` or `<module>.queue.[<channel>.]error.<descriptor>`:

- A module running one queue has no channel segment: `{ "queue": { "<process>": "…", "error": { "<descriptor>": "…" } } }`.
- A module running several queues keys the queue named for the module at the top and nests each channel queue under its lowercase channel name, an `EnumNotificationChannel` value (`email`, `push`, `sms`): `{ "queue": { "<process>": "…", "error": { … }, "email": { "<process>": "…", "error": { … } }, "push": { … } } }`.

## Every key lands in every language directory

A key added to one directory only resolves to the path string in the others. An exception, a `@Response` message, a validation message, and queue text each add their key everywhere.

| Producer | Path |
| --- | --- |
| an exception | `super('<module>.error.<descriptor>')` (`exception-class.md`) |
| a success response | the `@Response('<module>.<action>')` argument (`http.md`) |
| a validation failure | `request.error.<constraint>`, resolved by `MessageService` |
| a push notification | `notification.notify.<kind>.title` / `.body` (`notification.kind.contract.ts`) |
| an SMS body | `notification.sms.<kind>` |
| an activity-log action | `activityLog.<action>` (`ActivityLogUtil.getDescription`, `src/modules/activity-log/utils/activity-log.util.ts`; `activity-log.md`) |
| a job's `IQueueResponse.message` | `<module>.queue.[<channel>.]<process>`, the `Enum<Module>[<Channel>]Process` value (`queue.md`, Messages) |
| a `QueueException` message | `<module>.queue.[<channel>.]error.<descriptor>` (`exceptions.md`, Messages) |
| an unknown error a processor throws | `queue.error.unknown`, the kit's queue key in `src/languages/en/queue.json` (`queue.md`, Processors) |
| an unknown job name | `<module>.queue.[<channel>.]error.unknownProcess`, property `process` (`queue.md`, Processors) |

The `@Response` argument is a path, not a sentence.

## Language

- Text for an internal reader (a job return value, a job failure): `queue.md`, Messages.
- Text answering a request (a response message, an exception the filter renders, a validation message) resolves in the request's `customLanguage` from `RequestLanguageStoreKey`.
- A log line is not i18n (`code-style.md`, Literal strings).

## Placeholders

`{name}` is fed by `messageProperties`: `super('user.error.importEmailExist', { messageProperties: { emails } })` (`UserImportEmailExistException`, `src/modules/user/exceptions/user.import-email-exist.exception.ts`). A placeholder with no property renders literally; every language file carries the same placeholder set for a key.

## Renaming a key

The key links an exception's `messagePath` to the JSON. Rename both halves together, in every language, in one change; `tsc` catches nothing.

## Reading a message in code

`MessageService.setMessage(path, options)` (`src/common/message/services/message.service.ts:92`) is the one entry point; a `customLanguage` outside `message.availableLanguages` falls back to `message.defaultLanguage` there (`filterLanguage`).

## Templates are not i18n

A rendered email body or term-policy document is a Handlebars template uploaded as seed data (`notification.md`, `seeding.md`). Template prose stays out of the language JSON, and a status message stays out of a template.
