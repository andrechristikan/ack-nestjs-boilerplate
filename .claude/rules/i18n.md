# i18n messages

Detail in `docs/message.md`. Translations live in `src/languages/<lang>/<module>.json`, loaded
by `nestjs-i18n` through `MessageModule.forRoot()`; the language resolver is the
`x-custom-lang` header, falling back to `message.language` config.

## The path IS the file plus the nested key (HARD)

`user.error.notFound` resolves to `src/languages/en/user.json` → `{ "error": { "notFound":
"…" } }`. The FILENAME is the first segment.

**Flat keys are forbidden.** `"error.notFound": "…"` written as a single string key does not
resolve, and nothing fails at build time — the response carries the raw path back to the
client instead of a message.

- File name = module prefix, camelCase, matching the module: `user.json`, `featureFlag.json`,
  `termPolicy.json`, `apiKey.json`, `activityLog.json`.
- Every key segment is camelCase (`rules/case-convention.md`).
- Success messages sit at the top level of the file, keyed by action (`"list"`, `"create"`,
  `"updateProfile"`). Errors sit under `"error"`.

## Every new key lands in EVERY language file

`src/languages/` has one directory per supported language. A key added to `en` and nowhere else
resolves to the path string for every other language. Adding an exception, a `@Response`
message, or a validation message means editing all of them.

## Where a path comes from

| Producer | Path |
|---|---|
| an exception | `super('<module>.error.<descriptor>')` in its constructor (`rules/exceptions.md`) |
| a success response | the `@Response('<module>.<action>')` argument (`rules/http.md`) |
| a validation failure | `request.error.<constraint>`, resolved by `MessageService` |

**The `@Response` argument is a message PATH, not a literal message.** A human-readable string
there ships untranslated.

## Placeholders

Placeholders are `{name}` and are fed by `messageProperties`:

```ts
super('user.error.passwordMustNew', { messageProperties: { period } });
```

A placeholder with no matching property renders literally. A property with no placeholder is
dead weight. **Every language file must carry the same placeholder set for a given key** — a
translation that drops `{period}` silently loses the value.

## Renaming a key is a two-sided edit

The key path is the link between an exception's `messagePath` and the JSON. Rename both halves
together, in every language, in the same change (`rules/naming.md`). Nothing about it fails at
`tsc`.

## Reading a message in code

`MessageService.setMessage(path, options)` is the one entry point. A service never reads a JSON
file, never concatenates a message, and never builds a user-facing sentence in code — the
sentence is the translator's, the path is ours.

## Templates are not i18n

A rendered email body or term-policy document is a Handlebars template, seeded as initial data,
rendered through the template service (`rules/notification.md`, `rules/seeding.md`). Do not put
prose that belongs in a template into a language JSON, and do not put a status message into a
template.
