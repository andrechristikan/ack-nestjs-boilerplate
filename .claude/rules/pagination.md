# Pagination

- `/admin/**` is offset; every other scope is cursor, with no `count`, `page`, or `totalPage`. `includeCount` is a repository-side argument.
- `PaginationService` (`src/common/pagination/services/pagination.service.ts`: `offset`, `cursor`, `offsetPage`) is injected in repositories, which return `IResponsePaginationReturn<T>`. Database-level only; the one exception is a computed result the domain scores in memory and pages with `offsetPage`.
- `PaginationOffsetQuerySchema` and `PaginationCursorQuerySchema` (`src/common/pagination/dtos/`) carry paging and `search` (trimmed, at most `PaginationDefaultMaxSearchLength`), no `orderBy`. A list query DTO `.extend`s one, overriding the `search` meta to name its allow-list, plus filters; a list with no search drops it with `.omit({ search: true })`. A sortable list declares `orderBy` inline, no schema factory: a union of `z.templateLiteral([z.enum(<AllowList>), ':', z.enum(EnumPaginationOrderDirectionType)])`, its `z.array`, and `z.literal('')`, `.optional().meta({ … })` (`src/modules/user/dtos/request/user.list.request.dto.ts:21-41`); an unlisted field or direction answers 422 from zod. The controller binds one `@Query({ schema })`; the HTTP service passes the DTO to `PaginationQueryUtil.offset` / `.cursor` (`src/common/pagination/utils/pagination.query.util.ts:312`, `:359`) with `availableSearch` and `availableOrderBy` (`[]` for a list with no sort), builds filters with the util's helpers, and merges `storePatch` into `RequestStoreService` under `PaginationStoreKey`. The util stores both lists for the response metadata only, validates no `orderBy`, and injects no store. Domain and repository take `IPaginationQuery*Params`.
- Allow-lists live in `<module>.list.constant.ts` as `as const` tuples `z.enum` accepts: a Prisma-backed list holds `Prisma.<Model>ScalarFieldEnum.<field>` members and `satisfies ReadonlyArray<Prisma.<Model>ScalarFieldEnum>`; a computed list `satisfies ReadonlyArray<keyof I<Row>>`. A filter helper takes `Prisma.<Model>ScalarFieldEnum.<field>`. An `orderBy` key names a field the row carries.
- `availableOrderBy` in the response pagination metadata is mandatory (`src/common/response/dtos/response.pagination-metadata.dto.ts:96`). Every `availableOrderBy` field on a cursor route is immutable and non-null on every row the route's `where` returns; the test for immutable is whether a write path exists. Split `<Module>CursorAvailableOrderBy` from `<Module>DefaultAvailableOrderBy` only when the sets differ.
- A filter is a typed structure from the helpers; no `Record<string, unknown>`, no raw `filter` string, no `JSON.parse` into `where`. the util output types carry no `include`, `select`, or `includeCount`; `select` and `include` are exclusive; a row narrower than the model takes a `*Select` constant pinned by `Prisma.<Model>GetPayload<{ select: typeof <Const> }>`.
- The cursor token carries `{ values, fingerprint, firstPageAt }` only, sealed by `HelperEncryptionService.aes256Encrypt` under `PaginationCursorEncryptionPurpose` with the `app.encryptionSecretKey` root, so a client can neither read nor change it: `values` holds the last row's value of every `orderBy` term, tiebreak included; the fingerprint is a hash of the canonicalized `{ where, orderBy }` (`PaginationService.fingerprint`), and a mismatch raises `PaginationInvalidCursorPaginationParamsException`. `firstPageAt` is the first page's time: `PaginationQueryUtil.cursor` sets it on every `IPaginationQueryCursorParams`, from the token on a later page and from `HelperDateService` on the first. A time filter in a cursor `where` reads `firstPageAt` and stays in `where`, never `HelperDateService`, because a fresh clock changes the fingerprint and the next page answers 422. A read that skips `PaginationQueryUtil` passes its own fixed time as `firstPageAt`. A client sends the same filter, sort, and search on every page; one that changes any of them sends no cursor and restarts at the first page; the server answers the mismatch 422 and never resets it. `PaginationService.cursor` reads the next page through a keyset filter built from `values` and joined to `where` by `AND`, never Prisma's `cursor` argument or `skip`, so a last row that left `where` or was deleted moves no page boundary. A `select` missing a sort field gains it for the read, and the field leaves the returned rows. A null or absent sort value on the last row throws `PaginationInvalidCursorDataException`; a `Date` value is tagged under `PaginationCursorDateKey`, so a date-shaped string stays a string. `PaginationService` appends the tiebreak to every `offset` and `cursor` `orderBy` (`PaginationService.resolveOrderBy`): an empty `orderBy` becomes `PaginationDefaultOrderBy`, then `{ <field>: <direction of the last term> }` follows, the field `id` (`PaginationDefaultCursorField`) on `offset` and `cursorField` on `cursor`, skipped when a term already names it. A repository, domain, or HTTP service never adds its own tiebreak term to `orderBy`; `metadata.orderBy` omits it. A tiebreaker fixes ties, not a mutating key.
- Date bounds use `EnumPaginationFilterDateBetweenType`; the interceptor reads `EnumPaginationType` off the return. OpenAPI list params come only from the zod schema.
