# Pagination

The cursor token, the kit utils, and the keyset read: `pagination-kit.md`.

- `/admin/**` is offset; every other scope is cursor, with no `page` or `totalPage`, and no `count` unless a repository passes `includeCount`, a repository-side argument a client never sets.
- `PaginationService` (`src/common/pagination/services/pagination.service.ts`: `offset`, `cursor`) is injected in repositories, which return `IResponsePaginationReturn<T>`, and is database-level only. An analytic pipeline list: `analytic.md`.
- A generated analytic list pages its snapshot items through `PaginationService.offset` in `AnalyticSnapshotRepository`, sorted by `AnalyticSnapshotOrderBy` (`highestValue`, `value` descending and the `defaultOrderBy`; `key`), or `AnalyticImpossibleTravelOrderBy` (`highestValue`, `recent` by `occurredAt` descending, `key`) for the one signal whose items set `occurredAt`: a preset sorts by a field the list's rows set. These are item columns whose meaning differs per signal. The repository never swaps in a sort. Its return carries `computedAt` in `metadata`, which `ResponsePaginationInterceptor` copies into the response metadata.
- A repository calls `paginationService.cursor(client.<model>, args)` or `.offset(...)` in one statement with no generic arguments; the delegate is typed (`IPaginationDelegate`), and `where`, `select`, `include`, and the row type infer from the Prisma delegate.
- `PaginationOffsetQuerySchema` and `PaginationCursorQuerySchema` (`src/common/pagination/dtos/`) carry paging and `search` (trimmed, at most `PaginationDefaultMaxSearchLength`), no `orderBy`. A list query DTO `.extend`s one, overriding the `search` meta to name its allow-list, plus filters; a list with no search drops it with `.omit({ search: true })`. A list declares `orderBy` inline, no schema factory: a union of `z.enum(Enum<Module>[<Concern>]OrderBy)`, with no cast, and `z.literal('')`, `.optional().meta({ … })` naming the presets and the default one, with no array member (`UserListRequestSchema` `orderBy`, `src/modules/user/dtos/request/user.list.request.dto.ts`). A request names at most one preset, never a field or a direction; an unknown name or a repeated parameter answers 422 from zod. The controller binds one `@Query({ schema })`; the use case passes the whole DTO to `PaginationQueryUtil.offset` / `.cursor` (`src/common/pagination/utils/pagination.query.util.ts`) for params, with `availableSearch`, `orderBy: <Module>[<Concern>]OrderBy` (its preset constant) and the required `defaultOrderBy: Enum<Module>[<Concern>]OrderBy.<member>`, never terms and with no runtime check (the preset `''` or an absent request `orderBy` takes; `pnpm typecheck` rejects a name the constant lacks), and, on `.cursor`, the required `options.scope`, builds filters with `PaginationFilterUtil`, and merges `storePatch` into `RequestStoreService` under `PaginationStoreKey`. `PaginationQueryUtil` stores the preset name used and the preset names for the response metadata only, validates no `orderBy`, and injects no store. Service and repository take `IPaginationQuery*Params`, which carry no type argument: `where` is the search `IPaginationSearchWhere`, and the repository merges it into its model's `where`.
- Every list sorts by named presets the backend defines: one `<Module>[<Concern>]OrderBy` constant in `<module>.list.constant.ts` keyed by the members of its string enum, never plain string keys, `Enum<Module>[<Concern>]OrderBy` (`<module>.enum.ts`), `{ [Enum<Module>[<Concern>]OrderBy.<member>]: [...terms], … }`, `as const satisfies IPaginationOrderByPresets<Prisma.<Model>ScalarFieldEnum, Enum<Module>[<Concern>]OrderBy>` for a Prisma-backed list or `IPaginationOrderByPresets<keyof I<Row>, Enum<Module>[<Concern>]OrderBy>` for a computed one (`src/common/pagination/interfaces/pagination.interface.ts`), never the bare type, so a term key the model or row lacks, or an enum member with no preset, fails `pnpm typecheck`. A constant holds at least one preset and carries no required `default` key; a preset's name says what its order means (`latest`, `mostCount`, `recentlyJoined`), a text field keeping its field name, and no preset repeats another's terms; a preset is an array of terms, each `{ [<field>]: EnumPaginationOrderDirectionType.<direction> }` naming one field the row carries. Every list route's `@Doc` `description` names its presets with their order and marks the default (`orderBy presets: latest (createdAt descending, default), name (name ascending).`). A search allow-list stays an `as const` tuple; a filter helper takes `Prisma.<Model>ScalarFieldEnum.<field>`.
- The response pagination metadata carries `orderBy`, the preset name used, and `availableOrderBy`, the preset names, as strings (`ResponsePaginationMetadataSchema`, `src/common/response/dtos/response.pagination-metadata.dto.ts`); a paginated route that left no `PaginationStoreKey` entry throws `RequestContextMissingException` (500), with no fallback value. Every field of every preset on a cursor route is immutable and non-null on every row the route's `where` returns; the test for immutable is whether a write path exists.
- A multi-field sort is a preset holding several terms.
- A filter is a typed structure from `PaginationFilterUtil` (`src/common/pagination/utils/pagination.filter.util.ts`: `equalBoolean`, `equalString`, `equalNumber`, `notEqual`, `inEnum`, `ninEnum`, `dateBetween`); no `Record<string, unknown>`, no raw `filter` string, no `JSON.parse` into `where`. The util output types carry no `include`, `select`, or `includeCount`; `select` and `include` are exclusive; a row narrower than the model takes a `*Select` constant pinned by `Prisma.<Model>GetPayload<{ select: typeof <Const> }>`.
- `scope` is one constant per cursor endpoint, so a token issued at one endpoint answers 422 at another even when its payload matches.
- A mismatch raises `PaginationInvalidCursorPaginationParamsException` (422). A client sends the same filter, sort, and search on every page; one that changes any of them sends no cursor and restarts at the first page; the server never resets it.
- Server-built `where` (owner id, workspace, a clock) is outside the fingerprint and applies on every page. A clock filter in a cursor `where` reads `HelperDateService` on each page.
- A read that skips `PaginationQueryUtil` (a processor) has no client request and passes its scope constant directly as `fingerprint`; its token stays a local variable, never sent to a client or persisted.
- A cursor `select` carries every sort field and the tiebreak `id`; `PaginationService` adds nothing to `select`.
- `PaginationService` appends the tiebreak to every `offset` and `cursor` `orderBy` (`PaginationQueryUtil.resolveTiebreak`): an empty `orderBy` (only from a read that skips `PaginationQueryUtil`) becomes `PaginationDefaultOrderBy`, then `{ id: <direction of the last term> }` (`PaginationDefaultCursorField`) follows, skipped when a term already names it. A repository, service, or use case never adds its own tiebreak term to `orderBy`; the metadata never shows it.
- A query param filtered against an enum is a field on the list schema; the use case applies `PaginationFilterUtil.inEnum` / `.ninEnum` with the default set as a PascalCase constant in `<module>.list.constant.ts` (`UserDefaultStatus`, `src/modules/user/constants/user.list.constant.ts`). Never a hand-parsed `@Query` plus a manual `includes`.
