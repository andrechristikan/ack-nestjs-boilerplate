# I18n Guide

This guide shows how to add a localized message and a new language, for a developer who adds a response, an error, or a language.

## Prerequisites

- The module that owns the message, and the language file of that module in `src/languages/<language>/` (`<module>.json`, camelCase).
- A running API for checks 1 to 4 ([Installation][ref-doc-installation]).

## Steps

### Add a message

1. Choose the path. A success message is `<module>.<action>`, and an error message is `<module>.error.<descriptor>`. The first segment is the file name and every segment is camelCase. A module whose folder name is kebab-case takes the camelCase file name: `api-key` is `apiKey.json`, and `term-policy` is `termPolicy.json`.
2. Add the key to `src/languages/en/<module>.json`, and to the same file of every other language directory. A module with no language file yet gets a new file in every language directory, holding `{}` and then the key. Success messages sit at the top level and errors sit under `error` (`src/languages/en/role.json`, an excerpt):

    ```json
    {
        "error": {
            "notFound": "Sorry, we couldn't find the requested role.",
            "exist": "A role with this name already exists."
        }
    }
    ```

    A success message is one top-level key, as in `src/languages/en/hello.json`:

    ```json
    {
        "hello": "Hello! Welcome to our service."
    }
    ```

3. Write a placeholder as `{name}` and keep the same placeholders in every language. The code fills them from `messageProperties`. A placeholder with no property renders as written.
    - An exception passes the properties to `super(...)`, and the constructor parameters name them (`src/modules/password-history/exceptions/password-history.must-new.exception.ts`):

        ```typescript
        constructor(readonly period: number) {
            super('passwordHistory.error.mustNew', {
                messageProperties: { period },
            });
        }
        ```

    - A response returns the properties in the `metadata` of the use case result. This use case fills the `{count}` of `notification.markAllAsRead` (`src/modules/notification/use-cases/notification.mark-all-as-read.use-case.ts`):

        ```typescript
        return {
            metadata: {
                messageProperties: {
                    count,
                },
            },
        };
        ```

4. Use the path, never the sentence:
    - A response passes the success path to its decorator: `@Response('role.create', { schema: RoleSchema })`.
    - An exception passes the error path to `super(...)`: `super('role.error.notFound')`.
    - Code that needs a message of its own calls `MessageService.setMessage(path, { customLanguage, properties })`.
5. Rename a key in the JSON and in every use of its path in the same change, in every language. The compiler does not check a path.

### Add a language

1. Copy the English directory and translate every file. The new directory name is the language code:

    ```bash
    cp -R src/languages/en src/languages/id
    ```

2. Add the language to `EnumMessageLanguage` in `src/common/message/enums/message.enum.ts`. `message.availableLanguages` is built from this enum, and `en` stays the default:

    ```typescript
    export enum EnumMessageLanguage {
        en = 'en',
        id = 'id',
    }
    ```

3. Restart the API so the loader reads the new directory.

## Check the result

1. Request a route in the new or changed language. The public hello route needs no key:

    ```bash
    curl -i -H 'x-custom-lang: id' http://localhost:3000/api/public/hello
    ```

2. Read the `message` field of the body, and the `x-custom-lang` response header. The header holds the language the request resolved to.
3. Send a language the project does not list. The response falls back to `en`:

    ```bash
    curl -i -H 'x-custom-lang: xx' http://localhost:3000/api/public/hello
    ```

4. Trigger an error whose message has a placeholder and read the filled sentence. An empty body on a route with a request schema fails validation, and each entry of `errors` fills `{property}` with the field name. This request sends an empty body to the credential login route with an API key from the seed:

    ```bash
    curl -s -X POST -H 'x-api-key: <key>:<secret>' -H 'content-type: application/json' -d '{}' http://localhost:3000/api/v1/public/user/login/credential
    ```

5. Search for the path in the language directories to confirm that each carries it. The pattern names the file and the key, and the search prints one line per language:

    ```bash
    grep -n '"notFound"' src/languages/*/role.json
    ```

A key missing from a language other than the default shows the default language's text. A key missing from the default language resolves to the path string, so a raw path in a body marks a missing key.
